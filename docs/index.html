pocket-dial

A SIP PBX on one ESP32-S3. No router, no server, no cloud.

Flash a board · Quickstart · Features · Hardware · Security · Source · Releases

What it is

Point SIP phones at a small board and they can call each other, transfer, park, page and forward, the way they would on a rack-mounted PBX. The board handles registration and call control. Extension-to-extension audio goes straight between the phones, so the board stays out of the media path unless a feature needs it there (echo test, conference, voicemail, hold music, an outside line).

The same C++17 engine builds as a desktop binary for Linux, macOS and Windows, which is how most of it is tested.

Quickstart

On a board. Use the browser flasher (Chrome, Edge or Opera on a desktop, over USB). It picks the image for your board, writes it, and can seed Wi-Fi, a WPA2 passphrase for the access point and the registrar mode before first boot. Prefer the command line? See FLASHING.md.

On a PC or a Raspberry Pi. No ESP32 needed:

# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/GlomarGadaffi/pocket-dial/main/install.sh | sh

# Windows (PowerShell)
irm https://raw.githubusercontent.com/GlomarGadaffi/pocket-dial/main/install.ps1 | iex

From source.

cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/SipServer --ip 127.0.0.1 --port 5060 --web 8080

Open http://127.0.0.1:8080, register two softphones at sip:127.0.0.1:5060 as 1001 and 1002, then dial 777 for an echo test or 999 to page every phone. The full walkthrough is the setup guide.

What the phones get

  • Extension-to-extension calls with PCMU, PCMA or G.722, whatever the two phones agree on.
  • Blind transfer, and attended transfer with REFER + Replaces (RFC 3891).
  • Hold and resume, UPDATE (RFC 3311), session timers (RFC 4028).
  • Call park: dial an orbit 700–709 to park, dial it again from any phone to pick up.
  • Call pickup: *8 for your group, **<ext> for one extension.
  • Ring groups, ring-all or hunt down the list.
  • Paging zones 980–989, and 999 to page everyone.
  • Forwarding (unconditional, busy, no answer) and do-not-disturb per extension, with star codes from the handset.
  • BLF lamps through the dialog event package (RFC 4235).
  • Meet-me conference on 888, voicemail, hold music, and a dial plan of up to 16 rules.
  • Outside lines through a cloud media anchor (3CX, Apidaze). The direct carrier SIP trunk is shelved in favour of the anchors (ADR-002).

Not every one of these has run on real hardware yet. The feature roadmap says which have, and which have only passed the host tests.

Read this before you plug it in

pocket-dial is built for a flat, trusted local network. Out of the box:

  • The wifi image's access point is open. Anyone in radio range can join. WPA2 is one setting away and encrypts the dashboard, the signalling and the call audio at once.
  • The registrar starts in Learn mode: a new phone is adopted on its first REGISTER, with no password. Promote it to Secured, or switch the whole registrar to Secure, and SIP digest auth is required.
  • The dashboard ships with the login admin / admin and refuses to do anything until you replace it. On a fresh board the real control is who gets to the dashboard first.
  • There is no flash encryption and no Secure Boot. Whoever holds the board holds its secrets.

So: do not expose UDP 5060 or the dashboard to the Internet. Not with a port forward, not “just for a minute”. The threat model lists what is defended, what is not, and why.
