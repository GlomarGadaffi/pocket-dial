pocket·dialswitchboard

A SIP PBX on one ESP32-S3. No router, no server, no cloud.

Flash a board · Quickstart · Features · Hardware · Security · Source · Releases

What it is

Point a few SIP phones at a small board and they can call each other, transfer, park, page and forward, same as on a rack-mounted PBX. The board handles registration and call control; the audio goes phone to phone. It only touches media when a feature actually needs it: echo test, conference, voicemail, hold music, an outside line.

The same C++17 engine also builds as a plain desktop binary for Linux, macOS and Windows. That’s where most of the testing happens.

Quickstart

Got a board? Plug it in over USB and open the browser flasher (Chrome, Edge or Opera, desktop only). It picks the right image, writes it, and can set up Wi-Fi, a WPA2 passphrase for the access point and the registrar mode before the first boot. If you’d rather do it from a terminal, FLASHING.md has you covered.

No board? Run it on a PC or a Raspberry Pi:

# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/GlomarGadaffi/pocket-dial/main/install.sh | sh

# Windows (PowerShell)
irm https://raw.githubusercontent.com/GlomarGadaffi/pocket-dial/main/install.ps1 | iex

Or build it yourself:

cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/SipServer --ip 127.0.0.1 --port 5060 --web 8080

Then open http://127.0.0.1:8080, point two softphones at sip:127.0.0.1:5060 as 1001 and 1002, and dial 777 for an echo test or 999 to page everyone. The setup guide walks through the rest.

What the phones get

  • Extension-to-extension calls with PCMU, PCMA or G.722, whatever the two phones agree on.
  • Blind transfer, and attended transfer with REFER + Replaces (RFC 3891).
  • Hold and resume, UPDATE (RFC 3311), session timers (RFC 4028).
  • Call park: dial an orbit 700–709 to park, dial it again from any phone to pick up.
  • Call pickup: *8 for your group, **<ext> for one extension.
  • Ring groups, ring-all or hunt down the list.
  • Paging zones 980–989, and 999 to page everyone.
  • Forwarding (unconditional, busy, no answer) and do-not-disturb per extension, with star codes from the handset.
  • BLF lamps through the dialog event package (RFC 4235).
  • Meet-me conference on 888, voicemail, hold music, and a dial plan of up to 16 rules.
  • Outside lines through a cloud media anchor (3CX, Apidaze). A direct carrier SIP trunk is shelved for now; ADR-002 explains why.

Not all of this has been exercised on real hardware yet. The feature roadmap is honest about which features have, and which have only passed the host tests.

Read this before you plug it in

pocket-dial assumes a flat, trusted local network. Out of the box:

  • The wifi image boots an open access point. Anyone in radio range can join. WPA2 is one setting away, and it covers the dashboard, the signalling and the call audio in one go.
  • The registrar starts in Learn mode: any phone that sends a REGISTER gets adopted, no password asked. Promote the phone to Secured, or flip the whole registrar to Secure, and SIP digest auth kicks in.
  • The dashboard ships as admin / admin and won’t do anything until you change it. On a fresh board, whoever reaches the dashboard first owns it.
  • There is no flash encryption and no Secure Boot. Whoever holds the board holds its secrets.

Which all adds up to one rule: do not expose UDP 5060 or the dashboard to the Internet. Not with a port forward, not “just for a minute”. The threat model spells out what’s defended, what isn’t, and why.
